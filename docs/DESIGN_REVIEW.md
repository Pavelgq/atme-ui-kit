# Дизайн-ревью ATME UI Kit

**Дата:** 13 февраля 2025  
**Опыт ревьюера:** 8+ лет в продуктовом дизайне

---

## 1. Общая оценка

Библиотека имеет хорошую архитектуру: чёткое разделение токенов, темизация через CSS-переменные, консистентная система spacing. Martian Grotesk — смелый выбор, придаёт узнаваемость. Вместе с тем есть несколько критичных моментов, влияющих на консистентность, доступность и масштабируемость.

---

## 2. Критичные проблемы

### 2.1 Семантика состояний кнопки (primary)

**Сейчас:** В `Button.module.pcss` primary использует `--palette-primary-hover` как дефолтный фон.

```css
/* Строка 83-84 — дефолт */
background-color: var(--palette-primary-hover);
```

Это путает семантику: **main** должен быть основным состоянием, **hover** — при наведении.

**Рекомендация:** Дефолт → `main`, hover → `hover`, active → `active`. Либо переименовать токены в theme (default/rest вместо main), если текущее визуальное поведение — задумка.

---

### 2.2 Несогласованность secondary между темами

**Light:** secondary = оливковый (#c8d69b)  
**Dark:** secondary = фиолетовый (#a855f7)

Это разные цвета по hue, сатурации и «настроению». Пользователь, переключая тему, получает визуальный разрыв.

**Рекомендация:** Сохранять логическую связь:
- Либо обе темы — оттенки одной палитры (оливковый в обеих)
- Либо обе — фиолетовый
- Либо secondary = нейтральный акцент (серый с лёгким оттенком primary)

---

### 2.3 Жёстко заданные цвета

| Место | Проблема |
|-------|----------|
| `ActionButton.module.pcss` | Close = #dc6464, Expand = #78be78 — вне палитры |
| `Badge.module.pcss` | success/warning/error — `color: #ffffff` вместо `contrastText` |
| `global.css` | `:focus-visible` fallback `#0ea5e9` — не совпадает с primary |
| `Button/Badge ghost` | `rgba(0,0,0,0.05)` / `rgba(255,255,255,0.1)` — лучше вынести в токены |
| `SideMenu` tooltip | `rgba(0,0,0,0.8)`, `#fff` — не из темы |
| `Grid.stories.tsx` | `--color-semantic-surface-secondary` — переменная отсутствует |

**Рекомендация:**
- Добавить в палитру `info`, `overlay` (для hover ghost и overlay).
- Добавить `contrastText` для error/warning/success в `Palette`.
- Перевести ActionButton на `error.main` и `success.main` (или отдельные semantic-токены).
- Убрать fallback в `global.css` или сделать его зависимым от темы.

---

### 2.4 Отсутствие info-цвета

Для состояний «информация», «подсказка», «нейтральное уведомление» используется primary или ad-hoc цвета.

**Рекомендация:** Добавить в `Palette`:

```ts
info: {
  main: string;
  hover: string;
  active: string;
  contrastText?: string;
}
```

## 3. Тема светлая / тёмная

### Что сделано хорошо

- `data-theme` и `data-color-scheme` используются корректно.
- Ghost-кнопка учитывает тёмную тему через `rgba(255,255,255,0.1)`.
- CodeBlock проверяет `data-color-scheme="dark"` для Shiki.

### Проблемы

1. **Тени**  
   Используется `rgba(0,0,0,...)` — для тёмного фона тени выглядят слишком тёмными. Стоит добавить в `baseTheme` опциональные `shadowsDark` или ослабить opacity теней в dark-режиме.

2. **Контраст текста**  
   `text.secondary` (#a3a3a3) на `background.default` (#171717) — контраст ~4.5:1, на границе WCAG AA для мелкого текста. Для body-текста лучше увеличить контраст.

3. **Secondary в dark**  
   #a855f7 на тёмном фоне читается хорошо, но семантически не связан с light-secondary.

## 4. Чего не хватает

### 4.1 В палитре и токенах

- `info` (см. выше)
- `overlay` / `surfaceOverlay` для модалок, tooltips, ghost-hover
- `contrastText` для error, warning, success
- Тени, адаптированные под тёмную тему

### 4.2 В компонентах

- Состояние `focus` визуально есть, но стоит задокументировать focus ring (толщина, offset, цвет).
- Нет `Tooltip` как отдельного компонента (есть в SideMenu как локальный тултип).
- Нет `Modal`, `Drawer`, `Dropdown` — для полноценного UI-kit они важны.
- Нет `Skeleton` для состояний загрузки.
- `Select`, `Checkbox`, `Radio`, `Switch` — типичные примитивы отсутствуют.

### 4.3 В типографике

- Отсутствует явный `letterSpacing` в токенах.
- Нет семантических размеров (title, body, caption и т.п.), только числовые (xs, sm, base…).

---

## 5. Рекомендации по UX/UI

1. **Spacing**  
   У тебя `unit: 4` — это соответствует 4px. Добавь шкалу `4, 8, 12, 16, 24, 32, 48, 64` как явные значения для документации и Storybook.

2. **Border**  
   `base: 2px` — для input и кнопок иногда лучше 1px. Рассмотри `thin: 1px` и `base: 2px`.

3. **Анимации**  
   `heartPop`, `countBump` — хорошие микровзаимодействия. Добавь `prefers-reduced-motion` во все анимации (частично уже есть в SideMenu).

4. **Доступность**  
   - Минимальный контраст текста на фоне — 4.5:1 (AA).
   - Focus ring должен быть виден. Сейчас он есть — проверь контраст outline к фону в обеих темах.

## 8. Итог

Сильный фундамент: хорошая структура, использование CSS-переменных, темизация. Основные точки роста — консистентность палитры между темами, отсутствие хардкода и расширение семантических цветов. После правок по P0–P1 библиотека будет заметно надёжнее и проще в поддержке.
